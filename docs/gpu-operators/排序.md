<p class="gpu-operator__title">排序（bitonic sort + radix sort 的 1-bit split）</p>
<div class="gpu-operator__meta">
  <span>CUDA</span><span>P17</span><span>bitonic</span><span>radix sort</span><span>排序网络</span><span>scan 应用</span>

<p class="gpu-operator__label" id="problem">题目</p>

对 `n = 2²⁰` 个元素排序。

<dl class="gpu-operator__io">
  <dt>两条主线</dt><dd><strong>bitonic sort</strong>：比较网络，O(n log²n) 次比较，但<strong>访问模式完全固定、无分支、天然并行</strong>；<br>
<strong>radix sort</strong>：不比较，靠 <strong>直方图 + scan + scatter</strong>，O(n·位数)，是大规模排序的实际选择（cub 用它）</dd>
  <dt>面试现实</dt><dd>没人要求你手写完整的多 block radix sort。<strong>能写对块内 bitonic、
说清 radix 的三段结构（histogram → scan → scatter），就够了。</strong></dd>
</dl>

GPU 排序本身在推理里用得不多，但它是 **scan 的最佳应用场景**， 而且"为什么 GPU 不用快排"这个问题能很好地检验你对 GPU 执行模型的理解。

<p class="gpu-operator__label" id="signature">给定签名</p>

```cpp
void sort(float* a, int n);   // 升序，n 是 2 的幂
```

<p class="gpu-operator__label" id="tips">Tips</p>

- bitonic 的两层循环：`k` 是段长（2,4,8,…,n），`j` 是比较距离（k/2,…,1）。
- **方向由 `(i & k) == 0` 决定**，交替升降才能构造出"双调"序列；只让 `i < i^j` 的线程动手。
- 线程到下标的映射：`i = 2·tid - (tid & (j-1))`，保证每个线程恰好一对、且 i 的第 j 位是 0。
- **j < blockSize 时，一对元素一定在同一个 block 内** → 把这些步骤全放 shared 里一次做完，kernel 数大幅减少。
- radix 最简单的形式是 **1-bit split**：`0 的新位置 = exclusive_scan(!bit)`，`1 的新位置 = 总零数 + 前面 1 的个数`。天然稳定。
- ⚠ 1-bit split 里，**一个线程必须负责相邻的两个位置**，"按线程 scan"才等价于"按位置 scan"，稳定性才成立。

<p class="gpu-operator__label" id="implementations">分级实现</p>

=== "v0 block 内 bitonic sort"

    ⚠ 注意它的输出是**偶数块升序、奇数块降序**——这不是 bug，而是全局 bitonic 排序要求的"双调"结构（方向由**全局下标** `(base+i) & k` 决定）。单独当"块内排序"用时把方向改成局部下标即可。

     bitonic（双调）排序的核心是一个**固定的比较网络**：先把序列变成"双调"（先增后减），再用 log n 步归并成有序。两层循环 `k`（段长）和 `j`（比较距离），共 **log²n 步**，每步所有元素并行比较交换。

    关键三点：① **方向由 `(i & k)` 决定**，交替升/降才能构造出双调序列；② 只让 `i < i^j` 的线程干活，避免重复交换；③ **每步之间必须 `__syncthreads()`**。

    下标映射 `i = 2·tid - (tid & (j-1))` 保证每个线程恰好负责一对、且 i 的第 j 位是 0。

    ```cpp
    __global__ void bitonic_local_sort(float* __restrict__ a, int n){
        __shared__ float s[BS];
        const int base = blockIdx.x * BS, tid = threadIdx.x;
        s[tid]           = (base + tid < n)           ? a[base + tid]           : INFINITY;
        s[tid + BS / 2]  = (base + tid + BS/2 < n)    ? a[base + tid + BS / 2]  : INFINITY;
        __syncthreads();
        for (int k = 2; k <= BS; k <<= 1){
            for (int j = k >> 1; j > 0; j >>= 1){
                int i   = 2 * tid - (tid & (j - 1));   // 保证 i 的第 j 位是 0
                int ixj = i + j;
                bool up = ((base + i) & k) == 0;        // 这一段是升序还是降序
                if ((s[i] > s[ixj]) == up){ float t = s[i]; s[i] = s[ixj]; s[ixj] = t; }
                __syncthreads();
            }
        }
        if (base + tid < n)          a[base + tid]          = s[tid];
        if (base + tid + BS/2 < n)   a[base + tid + BS / 2] = s[tid + BS / 2];
    }
    ```

=== "v1 全局 bitonic sort（每步一个 kernel）"

    数组大于一个 block 装得下时，比较距离 j 可能跨 block —— **block 之间没法同步**，所以只能**每一步发一个 kernel**（kernel 边界天然是全局屏障）。

    代价：`log²n` 次 launch。n=2²⁰ 时是 **210 次 kernel launch**，而且每次都要把整个数组从 HBM 读一遍写一遍 —— **访存量是 O(n log²n)**，非常浪费。

    但它是理解 bitonic 的最好形式，也是"没有 shared 优化时"的基准。

    ```cpp
    __global__ void bitonic_global_step(float* __restrict__ a, int n, int j, int k){
        int i = blockIdx.x * blockDim.x + threadIdx.x;
        int ixj = i ^ j;
        if (ixj > i && ixj < n){                                  // 只让一对里下标小的那个动手
            bool up = ((i & k) == 0);
            if ((a[i] > a[ixj]) == up){ float t = a[i]; a[i] = a[ixj]; a[ixj] = t; }
        }
    }
    ```

=== "v2 shared 优化的全局 bitonic"

    观察：当比较距离 `j < BS` 时，**一对元素一定落在同一个 block 内**，那就不用回 HBM —— **把 j = BS/2 一直到 1 的所有步骤在 shared 里一次做完**。

    于是 kernel 数从 `log²n` 降到约 `log²(n/BS)` 量级，访存量也同比下降。

    这就是"**能在片上做完的，绝不回显存**"——和 FlashAttention、GEMM tiling 是同一个思想。

    ```cpp
    __global__ void bitonic_local_merge(float* __restrict__ a, int n, int k){
        __shared__ float s[BS];
        const int base = blockIdx.x * BS, tid = threadIdx.x;
        s[tid]          = a[base + tid];
        s[tid + BS / 2] = a[base + tid + BS / 2];
        __syncthreads();
        for (int j = BS >> 1; j > 0; j >>= 1){                    // 剩下的所有 j 全在 shared 里做
            int i = 2 * tid - (tid & (j - 1));
            int ixj = i + j;
            bool up = ((base + i) & k) == 0;            // 注意方向仍由【全局】下标决定
            if ((s[i] > s[ixj]) == up){ float t = s[i]; s[i] = s[ixj]; s[ixj] = t; }
            __syncthreads();
        }
        a[base + tid]          = s[tid];
        a[base + tid + BS / 2] = s[tid + BS / 2];
    }
    // host 侧的驱动：
    //   bitonic_local_sort<<<n/BS, BS/2>>>(a, n);                 // k = 2 .. BS 全部搞定
    //   for (k = 2*BS; k <= n; k <<= 1){
    //       for (j = k>>1; j >= BS; j >>= 1)                      // 跨 block 的步骤只能走 global
    //           bitonic_global_step<<<n/256, 256>>>(a, n, j, k);
    //       bitonic_local_merge<<<n/BS, BS/2>>>(a, n, k);         // j < BS 的部分一次做完
    //   }
    ```

=== "v3 radix sort（1-bit split，块内）"

    radix sort **不做比较**：按位分桶，从最低位开始逐位稳定重排，处理完所有位就有序了。**稳定性是它正确的前提**。

    最简单的形式是 **1-bit split**：对当前位做谓词 `p`，用 **exclusive scan** 算出所有 0 的前缀个数，于是

    `0 的新位置 = scan(!p)`，`1 的新位置 = 总的 0 个数 + (tid - scan(!p))`

    这天然是稳定的，而且**只依赖 scan**（P06 的模板直接复用）。32 位就是 32 轮。

    实际库用 4~8 bit 一轮（一轮处理 16~256 个桶），轮数少得多，但需要多桶的 scan 和更复杂的局部 rank。

    ⚠ **float 不能直接按位排**：要先做 P05 里那个保序 uint 变换。

    ```cpp
    __device__ __forceinline__ int warpScanIncl(int v){
        const int lane = threadIdx.x & 31;
        #pragma unroll
        for (int off = 1; off < 32; off <<= 1){
            int t = __shfl_up_sync(FULL, v, off);
            if (lane >= off) v += t;
        }
        return v;
    }
    __device__ __forceinline__ int blockScanIncl(int v, int& total){
        __shared__ int ws[32]; __shared__ int tot;
        const int lane = threadIdx.x & 31, wid = threadIdx.x >> 5, nw = blockDim.x >> 5;
        v = warpScanIncl(v);
        if (lane == 31) ws[wid] = v;
        __syncthreads();
        if (wid == 0){
            int w = (lane < nw) ? ws[lane] : 0;
            w = warpScanIncl(w);
            ws[lane] = w;
            if (lane == nw - 1) tot = w;
        }
        __syncthreads();
        if (wid > 0) v += ws[wid - 1];
        total = tot;
        return v;
    }
    __global__ void radix_sort_block(unsigned* __restrict__ a, int n){
        __shared__ unsigned s[BS], t[BS];
        const int base = blockIdx.x * BS, tid = threadIdx.x;
        s[tid]          = (base + tid < n)          ? a[base + tid]          : 0xffffffffu;
        s[tid + BS / 2] = (base + tid + BS/2 < n)   ? a[base + tid + BS / 2] : 0xffffffffu;
        __syncthreads();
        for (int bit = 0; bit < 32; bit++){
            // ⚠ 每个线程必须负责【相邻】的两个位置 2*tid 和 2*tid+1，
            //   这样"按线程 scan"才等价于"按位置 scan"，稳定性才成立。
            unsigned k0 = s[2 * tid], k1 = s[2 * tid + 1];
            int p0 = (k0 >> bit) & 1, p1 = (k1 >> bit) & 1;
            int totalZeros = 0;
            int myZeros = (1 - p0) + (1 - p1);
            int inc  = blockScanIncl(myZeros, totalZeros);
            int excl = inc - myZeros;                      // 我前面所有元素里 0 的个数
            int z = excl;                                  // running：0 的写入位置
            int o = 2 * tid - excl;              // running：我前面 1 的个数
            int d0, d1;
            if (p0 == 0){ d0 = z; z++; } else { d0 = totalZeros + o; o++; }
            if (p1 == 0){ d1 = z;       } else { d1 = totalZeros + o; }
            t[d0] = k0; t[d1] = k1;
            __syncthreads();
            s[tid] = t[tid]; s[tid + BS / 2] = t[tid + BS / 2];
            __syncthreads();
        }
        if (base + tid < n)         a[base + tid]          = s[tid];
        if (base + tid + BS/2 < n)  a[base + tid + BS / 2] = s[tid + BS / 2];
    }
    ```
