# MoE：总参数、激活参数、路由与均衡

<div class="study-notes study-analysis" markdown="1">

来源：提供的「算能科技二面」记录；对应模型结构[第 7～9 题](../index.md#q4)。跨卡执行与专家放置见[Expert Parallel](../../inference/analysis/11-ExpertParallel与负载均衡.md)。

## 1. 参数容量与实际工作不同 {#total-active}

简化假设公共部分参数为 P₀，有 E 个等大路由专家，每专家参数 Pₑ，每 token 选择 k 个：

- <strong class="study-key">总参数。</strong> `P_total=P₀+EPₑ`。
- **每 token 激活参数。** `P_active≈P₀+kPₑ`，共享专家可计入 P₀；不同统计还要明确 embedding 等参数的口径。
- **例子。** E=64、k=2，不代表显存只需保存 2 个专家。常驻部署需保存 64 个专家；一个 batch 也可能访问全部专家。

激活参数量可提示部分计算规模，不能单独预测运行时间。Attention 历史访问、专家权重流量、小 GEMM、路由与通信都要计入。

总参数主要决定权重容量，单 token 激活参数提示它访问/计算的专家子集；batch 很大时，不同 token 可以把所有专家都激活。例如每 token 选 2/64 个专家，32 个 token 最多形成 64 个 token—expert 对，已可能覆盖 64 个不同专家。

因此小 batch Decode 会读少量热点专家，大 Prefill 可能形成很多专家小矩阵；每个专家的实际 Mₑ 与布局、通信和 tile 效率共同决定时间。MoE 不能用 `激活参数/总参数` 直接预测显存需求或推理加速比。

## 2. Router 决定模型使用哪些专家 {#router-topk}

1. 根据 token 隐藏状态生成专家分数。
2. 按模型规则选择 top-k，可能有分组、bias 或归一化约束。
3. 执行选中专家，并用规定的权重合并；有 shared expert 时再合入共享分支。

例如 token x 选择专家 3、7，组合权重为 0.7、0.3，路由部分为 `0.7E₃(x)+0.3E₇(x)`。该例已给定权重，不表示所有 MoE 都用相同归一化方法。

### Router、选择分数和组合权重为什么要分开讲？

Router 根据隐藏状态 x 计算专家得分 r，可用 softmax、sigmoid 或模型规定形式。Top-k 选择哪几个逻辑专家，combine 用哪些权重，又可能有不同规则：例如先加负载 bias 选择专家，却用未加 bias 的原得分生成组合权重。不能把“最高分 k 个”自动理解成所有模型都对选中项再 softmax。

输出可写为 `y_routed=Σ_{e∈TopK(x)}w_e(x)E_e(x)`，shared expert 若存在则按模型定义合入。Shared 分支对所有 token 计算，仍增加权重与算术；稀疏路由通常替换 FFN，而 Attention、Norm 和残差不会因此消失。

选择逻辑专家决定模型函数，分配到哪个相同参数物理副本决定执行位置。Serving 负载均衡应区分这两个层次，不能为低负载随意把 token 改送另一个专家。

## 3. 为什么要训练均衡？ {#training-balance}

- **学习问题。** 过少被选的专家难以获得充分训练，热点专家可能承载大部分 token。
- **执行问题。** token 偏斜让专家 batch 和设备负载差异变大，慢设备限制协同执行。
- **辅助损失。** 一些模型鼓励分配更均衡，需要权衡目标权重与任务学习。
- **路由 Bias。** DeepSeek-V3 等设计用负载反馈调整选择 bias，减轻主要均衡机制对梯度的干扰；具体模型仍可能保留其他均衡目标，不能简单概括为完全没有辅助损失。

均衡有两个不同尺度。模型级均衡希望逻辑专家得到适量训练信号，避免少数专家垄断；设备级均衡希望一轮执行中各 rank 的工作接近。即使长期各专家均匀，某个短 batch 仍可能高度偏斜，放置到同一卡的热点专家还会叠加。

训练辅助损失或路由 bias 会影响选择分布；推理可用物理副本/映射保持同一个专家函数，同时分摊工作。把 token 改送另一个逻辑专家或丢弃超量 token 会改变模型计算，必须有模型本身的规则支持。

### 均衡辅助损失为什么可能和主任务形成取舍？

一种常见形式同时考察硬分配比例 f_e 和平均软概率 p_e，例如 `L_bal=αEΣ_e f_ep_e`，具体 top-k、normalization 与 stop-gradient 规则因模型而异。它通过 Router 概率的梯度鼓励分配更均匀，但权重 α 过大会干扰任务所需的专家专门化，过小又可能无法抑制热点。

负载反馈 bias 则可按窗口增减各专家选择倾向，不一定通过该辅助损失梯度改变 Router；某些模型对选择与组合分数分别处理，仍可能有额外序列级均衡目标。训练的长期均衡不能保证某个小 Decode batch 平衡，实际设备上还要测专家放置、短期 token 分布与通信。

## 4. 与 Serving 物理均衡的边界 {#physical-placement}

训练均衡影响逻辑专家的选择与学习；专家映射、热点复制和通信调度影响同一专家函数在哪里执行。后者可在保持逻辑路由的条件下改善负载，代价是额外权重、迁移及映射维护。改变 top-k、容量截断或丢 token 会影响模型语义，必须按模型定义处理。
