# MTP 与半自回归：多位置预测和候选依赖

<div class="study-notes study-analysis" markdown="1">

来源：提供的「百度昆仑芯一面」记录；对应模型结构[第 10～11 题](../index.md#q12)。术语描述候选建模，实际输出仍需遵守相应解码/验证机制。

## 1. 多位置训练目标与推理用途 {#future-objective}

普通 next-token 目标由位置 t 预测 t+1；MTP 扩展到 t+2、t+3 等未来位置，为表示提供更密集的训练信号。不同架构可采用独立偏移头，或让多层预测模块顺序连接。

这些额外模块可在训练后丢弃，或在支持的部署中作为 drafter。启用 MTP 并不代表原目标模型已经一次确认多个真实 token；候选还需验证，收益取决于 draft/verify 与状态成本。

若位置 t 的普通输出预测 token t+1，额外偏移 2 的目标预测 t+2，可写成 `−log p₂(x_{t+2}|可用的表示与条件)`；独立多头和串联预测模块给出的条件不同。训练用真实移位标签提供监督，不代表推理已经知道这些未来 token。

MTP 的训练收益与作为 drafter 的推理收益应分开评价。推理时多预测几个候选，还必须由正确验证规则确认；需要计算额外头/模块的时间、候选状态、连续接受长度和最终提交成本。

## 2. DeepSeek-V3 的因果链设计 {#causal-mtp}

DeepSeek-V3 技术报告采用顺序预测模块。深度 k 的模块结合前一深度表示与相应移位 token 的 embedding，预测更远一位；embedding 与输出 head 可共享，额外转换与 Transformer block 保留各自参数。

- <strong class="study-key">训练。</strong> 可以使用真实移位 token，维持每个深度的因果链，预测未来标签；具体损失与深度依配置。
- **候选生成。** 未来 token 未知时需用已经生成的候选或相应可用输入继续，不能把训练用真实未来 token 当成推理已知输入。
- **验证。** 目标模型检查候选并修正拒绝后缀，见 [投机推理](../../inference/analysis/17-投机推理与验证.md)。

这是一个具体 MTP 设计，不应将它概括为所有 MTP 都串行，或所有模型都共享同一种预测头。

### 顺序 MTP 模块怎样使用移位 token，又如何保证因果？

DeepSeek-V3 的额外深度 k 结合前一深度表示 `h_t^(k−1)` 与 token `x_{t+k}` 的 embedding，经归一化、拼接/投影和对应 Transformer block，产生用于预测 `x_{t+k+1}` 的表示。训练用真实移位输入，但模块不能看到自己要预测的标签；其因果 mask 与序列移位需要一致。

推理先从现有目标状态生成近一步候选，再把已生成候选作为下一个深度可用的移位输入；缺失未来 token 时不能读取训练标签。实际部署是否保留全部深度、共享 head/embedding 和怎样缓存 drafter 状态，都取决于模型与执行支持。

独立远偏移头省串行 draft 深度，却缺少部分近候选条件；链式 MTP 更接近条件序列，成本和误差传播也更多。最终仍需目标验证与状态修正，不能把训练多位置损失直接等同于目标模型一次提交多 token。

## 3. 独立并行与部分自回归的取舍 {#partial-autoregression}

| 组织 | 候选依赖 | 优点与限制 |
| --- | --- | --- |
| 独立偏移多头 | 从同一已知状态直接预测不同偏移 | 可并行，远位置可能缺少较早候选条件 |
| 串行候选链 | 每位使用较早候选及状态 | 条件接近自回归，draft 轮次较多 |
| 半自回归块/组 | 部分位置并行，块内或组间保留指定依赖 | 折中成本与条件表达，设计并不唯一 |

例如预测“北京大学”：第二个候选若知道第一候选为“北”，可用不同条件预测“京”；独立远偏移头也能学习这种规律，但缺少显式候选条件。改进是否成立取决于模型训练与依赖设计，不是串行越多就必然更准。

如果每位置的条件接受概率粗略相同为 a，且在已接受前缀条件下独立近似，γ 个候选的期望连续接受数为 `a+a²+…+a^γ`。γ=3、a=0.8 时为 1.952，而不是简单的 3×0.8=2.4；首次拒绝后的候选不再可提交。

半自回归可能通过给远位置更多先前候选信息提高条件接受率，也增加 draft 串行深度和误差传播。比较时不仅看单位置预测准确率，还要看各位置的条件接受曲线、验证浪费与每轮成本。此处是近似直觉；真实各位置接受概率不同，且最终提交还可能包含纠正或额外 token。

### 连续接受长度为什么比各头准确率更关键？

令 a_i 表示第 i 个候选在前 i−1 个都接受的条件下继续接受的概率，至少接受 i 个的概率是 `∏_{j=1}^i a_j`，期望接受前缀长度为各项之和。提升很后面一头的准确率，如果前面经常拒绝，能增加的真实提交很少。

例如 a₁=0.5、a₂=a₃=0.9，期望接受候选数为 `0.5+0.45+0.405=1.355`；先改善 a₁ 通常影响所有后续项。最终提交还可能包含拒绝处纠正或全部接受后的额外 token，因此用它评价速度时要加上 draft/verify/状态成本，并按真实输出预算处理。

## 4. 候选精度不能代替系统指标 {#proposal-metrics}

多位置预测质量、连续接受长度与最终质量是不同指标。半自回归可能提高接受长度，也会增加 draft 延迟和误差传播；比较时固定目标模型、采样设置、验证规则与工作负载，看最终提交 token 的成本。
