# SpMM 与稀疏格式：算术强度、元数据和执行取舍

<div class="study-notes study-analysis" markdown="1">

来源：提供的「英特尔校招面经」；对应 GPU与算子优化[第 51、53 题](../index.md#q37)，并补充量化、Bitmap 和性能分析题。

## 1. 为什么不能把稀疏率直接换成加速比？ {#sparse-roofline}

约定稀疏 `A[M,K]` 与稠密 `B[K,N]` 相乘，A 有 Z 个非零元素。直接按非零元素进行向量乘加时，有效运算量约 `F=2ZN`，但实际字节流量 Q 包含：

- 非零值、列/块索引、行边界或 bitmap，以及量化 scale。
- B 的读取，取决于非零位置、线程映射、缓存与跨输出列复用。
- 输出的读写、部分和归约、padding 与事务浪费。

应计算 `I=F/Q`，使用实际数据格式与 profiler 流量判断 Roofline。块内零值仍执行的计算应另计，不能混淆有效 FLOPs 与实际指令工作。

## 2. 剪枝、量化怎样改变瓶颈？ {#sparsity-bottleneck}

- <strong class="study-key">剪枝。</strong> 非零计算减少，但输出和部分数据访问不同比例下降；不规则 B 访问、长短行与解码可能使算术强度和利用率下降。
- **量化。** 数值载荷减少，可能提高算术强度；若低精度计算提速更多、索引成本仍高，瓶颈也可能转向供数或指令延迟。
- **元数据例子。** 理想 INT4 每值 0.5 byte，若每值附一个 4-byte 列索引，索引已是数值载荷的 8 倍。1000 个非零值需约 500 bytes 数值与 4000 bytes 索引，还未计行边界、scale 和对齐。
- **条件。** 结构化/块稀疏可摊薄索引并保留规则计算，较大 N 可改善复用；非结构化小 N 则可能更不利。不能得出“量化必然降低算术强度”。

设备带宽低且执行慢时，还需查 gather 延迟、指令解码、负载偏斜与并行度；这些不是饱和带宽意义上的 Memory Bound。

## 3. 格式取舍 {#sparse-formats}

| 格式 | 理想元数据特点 | 执行优势与代价 |
| --- | --- | --- |
| COO | 每非零值存行、列 | 构造直接；未按输出组织时可能需排序/归并或 atomic |
| CSR | 每非零值存列，另存 M+1 个行边界 | 方便逐行访问；行长度偏斜导致工作分配问题 |
| BSR/块稀疏 | 每块存索引和整块值 | 索引摊薄、易用矩阵 tile；块内零值与边缘 padding 消耗工作 |
| Bitmap 加紧凑值 | 固定区域按 bit 描述存在性 | 索引紧凑；需 popcount/偏移、映射及不规则加载 |
| 硬件结构化模式 | 固定组的位置编码 | 匹配支持的 sparse MMA；要求模型与布局满足指定模式 |

例如一个 16×16、INT4 的完整块载荷约 128 bytes，用一个 4-byte 块列索引，索引/值约 3.1%。但如果块内只有 16 个有效元素，保存和计算整块可能浪费大部分工作。压缩率与计算效率需要一起看。

### CSR 的一个实际执行例子

矩阵两行为 `[0,2,0,3]`、`[4,0,0,0]`，CSR 可表示为 `values=[2,3,4]`、`col=[1,3,0]`、`row_ptr=[0,2,3]`。输出第一行是 `2B[1,:]+3B[3,:]`，第二行是 `4B[0,:]`。CSR 连续存的是非零值和列号，访问稠密 B 的行仍由 col 决定，不能从 values 连续推断所有输入合并。

一个 warp 处理一稀疏行、lane 沿输出 N 分工，可以合并读取每个 B[k,:]；同一个非零值可广播或复用给多个输出列。若 lane 沿非零位置分工，会面对不规则 B 行和后续归约。N 大时前一种映射更能摊薄索引，小 N 或行长高度偏斜时需要不同工作组织。

### 长短行、块稀疏为什么会改变并行度？

一 warp 一行对长度 `[1000,1,1,1]` 的四行不均衡；可以按非零数量拆长行，但输出需要汇总部分和，代价类似 Split-K 的归约。BSR 把多元素共享一个索引，便于矩阵 tile 计算，却可能读取和计算大量块内零。格式、lane 映射、切分与归约共同决定效率，不是仅比较 metadata bytes。

## 4. 验证与适用范围 {#sparse-validation}

固定模型质量、稀疏模式、dtype 与 shape，比较稠密、结构化和自定义格式的预处理成本、workspace、实际字节与总耗时。静态权重可离线转换，动态稀疏的构造成本可能落在每次执行路径上；长期部署也需计入转换的摊销。
