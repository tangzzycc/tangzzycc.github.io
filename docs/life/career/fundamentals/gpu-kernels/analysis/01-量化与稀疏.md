# 量化与稀疏：容量、精度和执行成本

<div class="study-notes study-analysis" markdown="1">

来源：提供的「小鹏汽车一面」「腾讯 AI Infra 部门二面」「B站 AI Infra 二面」图片与记录，提取 INT8/INT4、量化粒度与稀疏执行的基础知识；对应[第 15～18、49～50、54 题](../index.md#q1)。

## 1. 量化主要节省什么？ {#quantization-benefit}

- <strong class="study-key">容量与流量。</strong> 权重量化降低参数存储和读取；激活量化可降低部分中间数据或通信载荷，收益取决于实际保存与传输格式。
- **计算。** W8A8 可使用支持的整数矩阵指令；W4A16 常在 tile 内解包、反量化后计算。INT4 权重存储不代表乘法使用 INT4 指令。
- **验证。** 同时检查任务质量、峰值内存、阶段耗时与端到端延迟，确认 kernel 确实消费压缩表示。

以一个参数张量为例，FP16 的每元素载荷是 2 bytes，INT8 为 1 byte，INT4 为半个 byte。压缩直接作用于存储和传输；只有执行侧一直读取压缩权重，并在局部 tile 解码或直接使用低精度指令，这份载荷差异才可能转化为速度收益。如果先把整份 INT4 权重展开为 FP16 再计算，稳态 GEMM 仍读 FP16，主要保留的是磁盘或加载阶段的压缩收益。

**量化的第一条因果链是：位宽降低 → 载荷减少 → 数据供给时间可能缩短；计算加速还需要匹配的执行路径。**
{.study-core}

对权重主导的单层，用权重元素数 P、权重位宽 b、有效带宽 BW 粗估，读取下界为 `Pb/(8BW)`。这是忽略 cache、元数据、激活和转换的下界。计算受限的 Prefill 即使降低权重读取，也可能几乎不改变总时间；带宽主导的小 batch Decode 才更可能直接受益。

## 2. INT4 相比 INT8 的取舍 {#int4-tradeoff}

- **理论载荷。** 每个权重 INT8 用 1 byte，INT4 用 0.5 byte；相同参数数目下纯载荷减半，实际还含元数据和对齐。
- **精度。** 4 bit 只有 16 个编码级别，8 bit 有 256 个；更少级别使范围与分辨率的取舍更紧，尤其要处理离群值。
- **性能。** 带宽节省可能被解包、scale 读取、反量化或低效 tile 抵消；Prefill 与 Decode 需要分别比较。

更少的量化级别意味着同样范围内步长更大。例如对称有符号 INT4 用整数 −7～7 表示范围 −7～7，scale=1；x=0.3 量化成 0，重构误差为 −0.3。INT8 若使用 −127～127，scale=7/127≈0.0551，同一个数可以重构为约 0.2756（整数编码为 5）。这个例子保持范围一致，说明分辨率差异；不意味着真实层误差能只按单个元素预测。

忽略截断时，round-to-nearest 的单元素绝对误差通常不超过半个 scale；离群值迫使 scale 变大，就会降低多数小数值的分辨率。校准、分组、离群值处理与 GPTQ/AWQ 等方法针对的正是输出敏感性和范围差异，不能只把 dtype 改成 INT4。

## 3. 权重量化与激活量化 {#weight-activation}

- **权重固定。** 可以离线校准、打包和重排；常见权重量化保留 FP16/BF16 激活，主要减少权重读取。
- **激活动态。** 分布随输入和层变化，可使用离线标定的静态 scale，或运行时计算动态 scale；要计入归约和转换成本。
- **计算类型。** 区分存储、乘法与累加精度，例如 INT8 乘法路径常用 INT32 累加；输出和 epilogue 可再转换精度。
- **W4A4。** 权重和激活都为 4 bit，但编码、scale/zero-point 和原生指令仍需说明；具体契约见 [W4A4 与稀疏元数据](07-W4A4与稀疏元数据.md)。

离线权重量化看到的是固定矩阵 W，校准数据用于估计哪些权重误差更影响 `XW` 的输出；动态激活量化每次看到的是不同 X，通常还要从当前 token/channel 归约范围。两者既可能使用不同分组轴，也可能采用不同 scale 生命周期。

对称整数乘法在同一 scale 组内满足 `x̂ŵ=s_x s_w(q_x q_w)`，可先整数累加再缩放。仿射量化则有 `(q_x−z_x)(q_w−z_w)`，展开后除了主乘积，还有行和、列和及零点交叉项。若 scale 沿 K 改变，必须先形成各组部分和再缩放；把整条 K 累加乘一个统一 scale 会改变数学结果。

### 为什么权重误差小，层输出仍可能误差大？

设线性层 `Y=XW`，X 为 `[T,K]`，W 为 `[K,N]`。量化产生误差 `E=Ŵ−W`，输出误差就是 `ΔY=XE`，所以评价权重量化应看 `‖XE‖²_F`，而不只看 `‖E‖²_F`。对一个输出通道、误差列向量 e，有：

$$
\|Xe\|_2^2=e^\top X^\top Xe.
$$

校准激活的幅度与相关性决定哪些误差更敏感；误差同样大的两组权重，经过不同的 X 后影响可能相差很多。

例如一行激活 `[100,1]`，两个候选误差分别为 `[0.1,0]ᵀ`、`[0,0.1]ᵀ`，权重误差范数相同，但输出误差为 10 和 0.1。大激活对应的输入通道更需要保护，这也解释了为什么仅按权重绝对值挑“重要参数”不充分。

### GPTQ 如何补偿，AWQ 为什么调整通道 scale？

GPTQ 用校准数据形成二阶近似，逐步固定权重为量化值后，利用尚未固定通道之间的相关性补偿误差。用 `H=XᵀX+λI` 表示带阻尼的重构二次型，其中 λ>0 改善有限校准数据下的病态或奇异矩阵；目标整体的常数系数不改变这里的最优解。

只看一次固定步骤：第 i 个误差固定为 δ，R 是其他尚可调整的通道，其误差为 e_R。将二次代价展开，对 e_R 求导：

$$
\begin{aligned}
L(e_R)&=H_{ii}\delta^2+2\delta H_{iR}e_R+e_R^\top H_{RR}e_R,\\
\nabla_{e_R}L&=2H_{RR}e_R+2H_{Ri}\delta=0,\\
e_R&=-H_{RR}^{-1}H_{Ri}\delta.
\end{aligned}
$$

若通道间不相关，H_Ri 为零，其他通道无法补偿；存在相关性时，调整剩余权重可抵消部分输出误差。这是连续二次目标的一步推导，实际 GPTQ 还要处理逐步量化约束，并使用分块、逆 Hessian/分解等实现，不会为每个元素重新求逆。

AWQ 使用激活统计选择通道缩放。对正对角矩阵 D，浮点计算满足 `XW=(XD⁻¹)(DW)`；在 DW 上量化后，输出变成 `XD⁻¹Q(DW)`。放大敏感权重通道再把输入反向缩小，可改变量化误差分配，同时保持未量化函数等价。缩放也会改变组内范围与其他通道误差，所以需要搜索与校准，不是无限放大某个通道。

**GPTQ 关注受激活相关性加权的输出重构与补偿；AWQ 用等价通道缩放保护敏感通道。两者都不能保证任意校准分布和任务无损。**
{.study-core}

Checkpoint 的 scale、zero-point、通道排列与 group 映射必须和执行 kernel 一致。启用 act-order 等重排时，量化逻辑分组未必就是物理相邻 K 元素；加载代码与 kernel 要一起理解，而不是只读取一个 `group_size` 配置。

资料：[GPTQ](https://arxiv.org/abs/2210.17323)、[AWQ](https://arxiv.org/abs/2306.00978)。

## 4. Scale 与 Group Size {#scale-group}

- **数值映射。** 常见仿射表示为 `q = clip(round(x/s) + z)`、`x̂ = s(q-z)`，其中 s 是正 scale，z 是零点。对称方案可使用隐式零点。
- **Scale 取舍。** 范围过小会截断大值，过大会让步长变粗；应结合校准与误差补偿选择，而非只取最大绝对值。
- **分组。** 例如 `W[N,K]` 沿 K 每 G 个元素共用参数，需要约 `N × ceil(K/G)` 个 scale。较小 G 通常更能适应局部范围，但增加元数据和访问成本。
- **执行契约。** 分组轴、尾组、scale dtype 与 kernel 支持必须匹配；Group Size 更小不保证端到端质量或性能更好。

沿用 `W[N,K]`，INT4 主载荷为 `NK/2` bytes，若每组只有一个 FP16 scale、K 可被 G 整除，scale 载荷为 `2NK/G` bytes，因此 scale 相对主载荷的比例为 `4/G`。G=128 时约 3.125%，G=32 时约 12.5%；有零点、其他参数或尾组时还要追加。

**Group Size 同时决定误差的局部性、元数据比例和 GEMM 沿 K 的缩放边界。**
{.study-core}

取一组数 `[0.1,0.2,0.3,7]`：用共同的 INT4 scale=1 时前三个值可能全部变为 0；若前三个值独立用较小 scale，可以保留更多差别。现实中不会随意按这个手工分组，而要按明确的 channel/K 轴和固定 G 划分。Kernel 必须从逻辑输出通道和 K 位置找到正确 scale，物理打包后的相邻字节不一定属于同一组。

### 动态激活 scale 为什么会成为额外瓶颈？

Per-token 动态量化通常先对 K 个特征求范围，再生成 scale 并编码输入。它需要一轮或多轮读取、max/absmax 归约、除法或逆 scale、round/clip 和压缩写入。若 Linear 本身很小，量化准备可能与矩阵乘耗时同量级；能否融合到读入 GEMM 的路径又受跨线程归约和 scale 就绪约束影响。

沿 K 分组时，每组 scale 要在本组乘积进入最终浮点累加之前可用。假设两个组整数部分和分别为 100、−100，scale 产品为 0.01、0.02，正确结果是 −1；先把整数部分和相加成 0 再缩放，会完全丢失结果。这是缩放的位置错误，不是普通浮点容差问题。

### 对称与非对称方案怎样影响 kernel？

对称方案常省掉显式零点；非对称方案可更好利用偏向一侧的数值范围，但整数点积需要处理 `Σ(q_x−z_x)(q_w−z_w)`。若一组内零点不变，展开为主点积、两个单边和及 `K_g z_xz_w`；其中 K_g 是该组实际长度，不能对尾组用完整 G。权重列和可离线计算，激活行和可能在运行时归约。压缩率、精度与新增修正指令因此需要联合比较。

## 5. 稀疏化如何与量化结合？ {#joint-compression}

- **两种压缩。** 剪枝减少保留元素，量化压缩保留值；需共同确定稀疏格式、量化参数与执行路径。
- **硬件条件。** 结构化模式如部分设备支持的 2:4 更容易使用专门矩阵指令；非结构化稀疏通常要额外索引与负载分配。
- **真实跳过。** 稠密 kernel 仍会计算存储为零的元素；只有压缩存储或跳过相应计算，才可能获得稀疏收益。
- **联合误差。** 可在剪枝后重新校准量化，或联合优化；顺序依算法而定。质量下降与索引、解码成本会使收益无法直接相乘。

联合压缩后每个保留值都需要两类信息：它位于原矩阵的哪里，以及它用什么量化参数解释。前者由稀疏索引/bitmap 表示，后者由 scale/zero-point 表示。压缩值数组的第 j 个元素不一定是原矩阵的第 j 个位置，不能直接用压缩下标寻找 per-channel 或 per-group scale。

先剪枝再量化时，删除权重改变了层输出和分布，原 scale/校准结果可能需要重新求取；先量化再剪枝时，也需区分“编码为零”与“逻辑零”。仿射量化中的零可能对应 q=z，按原始 bit 全零跳过会产生错误。最后应同时检查压缩格式正确性、联合任务误差和真实跳过的计算量。

## 6. 2:4 结构与硬件约束 {#structured-2of4}

NVIDIA 此处的硬件机制是相应 Sparse Tensor Core/MMA，支持规定的局部稀疏模式。非结构化稀疏则需要软件索引、解码与不规则调度；图片中的 Sparse Core 名字不足以证明存在任意稀疏通用加速单元，其他平台的同名术语需独立核对。

### 50% 非零为什么不代表能使用 2:4 Sparse MMA？

固定组 `[a,b,c,d]` 至多保留两个非零，数值与位置需编码为指令要求的 compressed operand 和 metadata。一个矩阵平均 50% 非零，仍可能有某组四个非零、另一组全零，不满足每组局部约束。压缩维度、operand、排列和 dtype 也属于硬件契约。

Sparse MMA 理想减少规定 operand 的乘法工作；另一 operand、输出和 epilogue 并不都减半，压缩值与 metadata 还要搬运和组装。若原瓶颈在读取另一矩阵、输出、索引或启动，就不应期待两倍端到端收益。模型质量还取决于剪枝/补偿训练，执行加速与质量保持需要独立验证。

## 7. SparseGPT、PPL 与“无损”结论 {#quality-ppl}

SparseGPT 使用校准激活的二阶近似信息，在删除权重时补偿剩余权重，降低层输出的重构误差。它是降低剪枝损伤的方法，不保证所有模型、稀疏度和任务保持原质量；与量化结合时还需控制校准分布和误差叠加。

对评估 token 的平均负对数似然，PPL 可写为：

$$
\mathrm{PPL}=\exp\left(-\frac{1}{N}\sum_i\log p(x_i\mid x_{<i})\right).
$$

越低表示模型给真实后继 token 的平均似然更高。Tokenizer、评估划分、上下文窗口、stride、mask 和 token 计数不同都会改变口径，单个 WikiText-2 PPL≈10 不证明精度无损。

比较原始、仅剪枝、仅量化及组合模型，在独立评估集上检查 PPL 差异和任务质量；例如 PPL 从 8 升到 10 与从 10.1 降到 10 含义不同。真实 INT4/稀疏 kernel 还需对照量化数学参考，区分算法误差与实现错误；语言 PPL 不能代替视频生成等不同业务的质量评估。

Group Size=128 只是配置，需明确权重/激活分组轴、动态/静态 scale 和支持条件。图片的“WCS ITEM”没有可确认的准确方法名或来源，本文不据此编造量化算法。

资料：[SparseGPT](https://arxiv.org/abs/2301.00774)、[PTX Sparse MMA](https://docs.nvidia.com/cuda/parallel-thread-execution/#warp-level-matrix-instructions-sparse-mma)。
