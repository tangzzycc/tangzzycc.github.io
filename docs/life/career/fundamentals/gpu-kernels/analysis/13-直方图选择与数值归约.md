# 直方图选择与数值归约：第 K 大、原子竞争和确定性

<div class="study-notes study-analysis" markdown="1">

来源：提供的「小鹏汽车三面」「阿里平头哥一面」记录；对应 GPU与算子优化[第 47、63～64 题](../index.md#q48)。这里整理 CUDA 编程题中的通用算法与性能知识。

## 1. 先明确第 K 大的定义与值域 {#histogram-selection}

令 K 从 1 开始，重复值按出现次数参与排名，必须满足 `1≤K≤N`。若要求第 K 个不同值，则应另设语义，不能继续用累计频数排名。

对取值属于整数 `[0,R)` 的数组，统计 `h[v]`，再构造升序 inclusive prefix sum `P[v]=Σ(u≤v)h[u]`。第 K 大等价于第 `N−K+1` 小，答案为第一个满足 `P[v]≥N−K+1` 的 v。

例如数组 `[7,2,7,4,1,4]`，K=3，目标升序排名为 4：

| 值 v | 1 | 2 | 4 | 7 |
| --- | --- | --- | --- | --- |
| 频数 h[v] | 1 | 1 | 2 | 2 |
| 累计 P[v] | 1 | 2 | 4 | 6 |

首个累计达到 4 的值是 4，与降序 `[7,7,4,4,2,1]` 一致。表格仅省略零频数 bin，完整直方图仍按值域索引。

复杂度约为 `O(N+R)`，空间约为 `O(R)`，还需并行统计与 scan 的实际成本。R 过大时完整直方图不合适；浮点粗分桶只能定位区间，需要在候选 bin 内继续选择。采用 radix selection 时还要定义有符号/浮点的有序编码以及 NaN、±0 的排序语义。

### 前缀和怎样并行，第 K 大为什么不必完整排序？

Histogram 将每个值的重复次数集中到 bin；scan 把 bin 频数转成排名区间，第 K 大只需找到包含目标排名的区间，不需要输出全部元素排序。有限整数值域 R 下，工作近似 N+R；若 R 远大于 N，清零和扫描反而浪费，排序/选择或多轮 radix 方法更适合。

CTA 内 scan 可先做 warp inclusive scan，再把各 warp 总和写 shared，由一个 warp 扫描 warp totals，最后给每个 warp 加前面 warp 的累计量。多 CTA 时，先产生 block totals，再扫描这些 totals 并回加，普通 block barrier 不能保证其他 CTA 已写完。计数溢出与 inclusive/exclusive 的偏移是正确性的一部分。

浮点粗分桶只能确定答案在哪个区间，不能直接把 bin 中心当精确第 K 大。Radix selection 可按有序 bit 编码逐轮计数并缩小候选集合，但 signed/浮点编码需让字典序对应数值序，还要约定 NaN 和 ±0。

## 2. Shared Histogram 降低全局原子竞争 {#shared-histogram}

典型多 kernel 流程：

1. 清零全局 histogram。每 block 协作清零自己的 shared bins，再同步。
2. 各线程以合并访问读输入，更新 block 局部 histogram；局部更新仍可能使用 shared atomic。
3. Block 同步完成统计，再把非零 bin 合并到全局；也可先写各 block 私有 histogram，再由第二阶段归约。
4. 全局统计完成后做 prefix scan 和排名定位，不能用普通 block barrier 代替跨 block 同步。

当有 Q 个 block、R 个 bins，局部 histogram 后的全局 atomic 上界约为 `Q×R`，原方案约为 N 次；若 R 大或 N 小，清零与合并成本可能让局部方案更慢。热点值集中时，同一 shared bin 的竞争也很高，可评估 per-warp histogram 或 warp 内同值聚合，但会增加存储、指令或合并成本。

计数类型必须能承载 N 及局部/全局累计结果。Shared Memory 占用约 `R×计数字节数`，使用 per-warp 副本时再乘副本数；容量和 occupancy 也约束 bins 大小。

## 3. “每线程多处理元素”不等于缓存复用 {#grid-stride}

Grid-stride loop 让每轮 warp 访问相邻元素，每线程累计多份输入，可控制 block 数并摊薄调度成本。若能在寄存器中对重复值局部计数，可能减少 atomic；若加载向量满足对齐，可能减少指令。

如果每个元素仍恰好读取一次，总必要输入载荷仍为 `N×输入元素字节数`。把循环变长没有自动产生 L2 时间复用。真实收益应检查：

- 合并事务与有效字节是否改善，是否消除了重复读取。
- 全局/shared atomic 次数、热点竞争与同步是否减少。
- 寄存器、shared 和驻留数量是否造成回退。
- 正式设备计时是否下降；缓存命中率只是辅助证据。

## 4. 精度、原子性与确定性分别是什么？ {#numerical-order}

浮点加法会舍入。例如 FP32 中 `(10⁸+(−10⁸))+1` 与 `10⁸+((−10⁸)+1)` 可分别得到 1 和 0。并行归约树、Split-K、atomic 更新顺序及 collective 算法都会改变求和顺序。

| 性质 | 提供的保证 | 不保证什么 |
| --- | --- | --- |
| Atomic add | 并发更新按原子操作处理，避免丢失单次加法 | 浮点更新按固定次序执行 |
| 固定划分和归约树 | 同环境下更可控的加法顺序 | 跨硬件/编译器自动 bitwise 相同 |
| FP32 累加低精度输入 | 常能减少累计舍入误差 | 输入量化误差消失或任意长归约无误差 |
| 整数计数/累加 | 无溢出时整数加法精确 | INT32 一定足以承载任意 N/K 与数值范围 |

FP16 常见规格为 5 位指数、10 位显式尾数；BF16 为 8 位指数、7 位显式尾数。BF16 范围接近 FP32，但不代表精度比 FP16 更高。INT4/INT8 还需处理 signedness、scale 和零点；最终输出类型不能代替实际乘法/累加路径。

“确定性”适合回答同输入、同环境是否可复现，“精度”回答误差大小，模型质量回答误差是否影响任务。固定顺序可能增加 workspace 或降低并行效率，需按需求比较成本。
