# 异构调度与跨帧缓冲：任务依赖、所有权和回压

<div class="study-notes study-analysis" markdown="1">

来源：提供的「小鹏汽车三面」记录；对应推理优化[第 42～44 题](../index.md#q83)。面经的单缓冲方案作为设计取舍，不视为所有设备上的最优实现。

## 1. 统一接口，显式保留设备约束 {#heterogeneous-dag}

把每帧处理表示为任务 DAG，例如 `CPU 预处理→NPU 编码→GPU 后处理→CPU 消费`。这是示例，实际算子放置需核对设备支持，不能假定 NPU/DLA 能运行任意大模型算子。

| 对象 | 需要描述的内容 |
| --- | --- |
| Task | 输入输出、依赖、frame ID、优先级/deadline、可执行 backend |
| Backend | 算子/dtype/shape 支持、提交队列、完成通知、工作空间、取消约束 |
| Buffer | 地址/设备可达性、layout、大小、版本、读写引用、就绪/可回收事件 |
| Scheduler | 就绪任务、设备队列、容量与带宽预算、估计成本、准入与回压 |

候选放置成本可初估为排队、转换/搬运、计算及后续关键路径的组合，但任务重叠和共享带宽会改变时间，不能把每条边独立成本机械相加。若换设备的计算省 1 ms，却多付 3 ms 转换与传输，设备利用率可能提高，端到端反而变慢。

端侧共享内存不意味着所有 backend 都能直接使用相同地址和布局。需核对映射、权限、DMA、cache 可见性、IOMMU 及 SDK 契约；队列和带宽在共享 DRAM 上也会竞争。性能评估包含持续运行的功耗、频率与温度。

### 统一调度如何同时表达依赖、资源和缓冲所有权？

把任务表示为 DAG 节点：包含输入输出 buffer、前置事件、可执行 backend、预计时间/数据量和 deadline。节点只有依赖完成、目标设备可用、buffer 可安全访问三项同时满足才能启动；完成事件推进下游，并在最后一个消费者结束后释放 buffer。

调度目标可以是单帧延迟或多帧稳态吞吐。CPU 预处理、NPU 编码、GPU 生成可以处理不同帧，但帧号与共享区域必须区分；最快单节点方案若引入多次昂贵跨设备转换，完整链路可能更慢。保留设备约束比一个只返回“任务完成”的统一 API 更有助于做正确规划。

## 2. 单缓冲竞争的最小例子 {#buffer-race}

设共享区域 S，生产者 P 为帧 f 写入，消费者 C 读取：

`P.write(f,S) 完成 → C.read(f,S) 完成 → P.write(f+1,S)`。

若 P 在 C 的读取实际完成前写 f+1，C 可能读到混合两帧的数据。Host 提交 C 后返回，只证明已提交，不能证明 C 完成读取。CPU mutex 只约束 Host 线程，除非设备接口明确同步完成，否则也无法保护异步设备访问。

安全复用需要两类依赖：

- 写完成后读，确保消费者看到有效数据。
- 所有消费者及在途传输完成后覆盖，确保旧数据不再被使用。

Buffer 应带 frame ID/版本和引用，避免迟到回调把已复用的新一代 buffer 标记可回收。非一致性平台还需 API 规定的 cache clean/invalidate 或 fence；信号和数据可见性要按实际内存模型建立。

设 CPU 为帧 n 写入缓冲，NPU 随后读取进行编码，GPU 再读取其输出。若 CPU 在 NPU 读完前开始写帧 n+1，缓冲中一部分位置可能属于旧帧，另一部分属于新帧；即使所有设备共享同一地址且没有额外拷贝，也会产生数据竞争。

单缓冲正确时序要求 `CPU写n完成→NPU读n完成→允许CPU写n+1`，如果 GPU 仍需原缓冲，则最后一个消费者结束才可覆盖。每设备的队列提交完成不代表执行完成，需要事件/fence 和对应可见性；帧号还需跟踪，不能用上一帧的完成信号放行下一帧。

## 3. 三种方案放在同一个边界比较 {#buffer-strategies}

| 方案 | 可获得的隔离 | 主要成本 | 必须建立的依赖 |
| --- | --- | --- | --- |
| 全量拷贝到消费者快照 | 消费者读取快照，源可在复制完成后复用 | 额外容量及一次源读/目标写 | 源写完→复制，复制完→消费/源覆盖 |
| 双缓冲 S0/S1 | P 写另一槽时 C 可读当前槽 | 额外一个槽、事件与槽管理 | 写就绪→读，槽读完→下一次覆盖 |
| 单缓冲完成事件控制 | 保持同一份数据，无额外快照 | 同一区域的重用等待、可能减少重叠 | 写完成→读，全部读完成→覆盖 |

设每帧复制 D 字节，一次完整复制会产生至少 D 字节源读取和 D 字节目标写入。延迟 `D/有效复制吞吐` 只是路径估算；共享 DRAM 流量、映射和同步还会影响总耗时。它不等于复制时必须另增 2D 容量。

若写一帧需 2 ms、读一帧需 5 ms，单缓冲同一区域的简化串行周期为 7 ms；双缓冲在资源独立、足够队列且无竞争时可接近 5 ms。若读更慢，第三帧写入仍要等待旧槽读完，两槽无法吸收无限积压。例子未计入首尾、输入到达或其他阶段。

若缓冲不同子区域的依赖独立，可以细分 tile/区域事件增加重叠，但必须证明每个消费者的实际访问范围；不能仅凭“单缓冲”推断必然全串行或必然无等待。

## 4. 回压和验证 {#backpressure}

没有可安全写入的槽时，阻止继续入场、等待或按业务规则丢弃未执行帧；不能覆盖仍在读取的数据。释放算力和释放 buffer 是不同事件，任务完成后的数据可能仍被下游消费。

验证用 frame 标记/校验、随机延迟和多消费者覆盖正确性，再记录真实设备完成时间、跨帧时间线、带宽、吞吐与尾延迟。Zero-copy 节省某些副本，不会消除必要的数据读写、可见性和生命周期管理。
