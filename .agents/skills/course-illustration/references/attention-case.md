## 为什么这张图具有教学连续性

固定同一组假设：一个三 token 请求、32 个 Query heads、8 个 KV heads、每 head 128 维，TP=1、无 bias/量化、无历史缓存的 causal prefill。

| 阶段 | 可追踪对象 | 需要读者看懂的变化 |
|---|---|---|
| Project | 同样的三个 token 行 | 每一行通过权重投影产生自己的 Q/K/V；按特征拆分，token 行保持独立 |
| Rotate | 同一 head 内的坐标对 | 位置改变 Q/K，V 保持原样；配对和变换紧邻显示 |
| Match + Mix | token 2、Query head 0 | 一行 Query 匹配三个 token 的 Key，产生三个位置权重，再加权三行 Value |
| GQA + Output | 同一份 K/V 与四个 Query | 一份 K/V 被四次独立计算使用，各自输出；选中的输出落到确定的拼接位置 |

这里的视觉动作是“投影—拆分—旋转—匹配—混合—共享—落位”。同一对象在不同阶段保持颜色和身份。不能只复制四个标题并放入解释段落。

## 真实迭代过的问题

1. **V 没有连到加权乘法。** 修订要求绿色 V 作为独立操作数连入乘法框顶部；紫色权重从左进入，不能把 V 连到权重。
2. **head 数标到了 token 轴上。** 修订为沿行宽放置 `32 heads × 128`，保持三条 token 行。
3. **输出映射挤在侧边。** 将整个映射区域移至底部通栏，给 O、展平视图和输出投影足够空间。
4. **RoPE 指数遗漏 i。** 明确要求 `θ = p × base^(−2i/128)`，核查成图而不只检查提示词。
5. **切片冒号变逗号。** 指定 `Q′[2:3, 0, :]` 保留 token 轴，形状为 `[1,128]`。
6. **高亮路径错接 head 3。** 明确从 `O[2,0,:]` 出发，指向 token 2/head 0 的格子。
7. **展平高亮覆盖两个 head。** 只高亮 token 2 的 `0:128` 区间；其他分段保留底色。

由此得到的可复用检查点是操作数完整性、轴含义、公式字符、源/目标身份及高亮范围；这些检查不只适用于 Attention。
