# 课程审阅与定稿检查

按事实正确性、教学逻辑、重复内容、可理解性、展示效果的顺序检查。发现问题要指出具体位置、读者会形成的错误理解及修改方向；不为了填满分类而制造意见。

## 正确性与证据

- 术语、公式、单位、形状和小例子的计算一致；简化条件清楚，不把特例写成通则。
- 源码版本、文件与行号支持实际结论，调用者、状态所有者和执行者没有混淆。
- 论文算法、生产实现、数学分块和硬件调度明确区分。
- 元数据与数值、逻辑与物理、视图与副本、启动配置与运行时状态没有混用。
- 性能解释对应明确负载与成本；操作数减少、HBM 读写减少和运行时间缩短不被视为同一结论。
- 尚未核实的内容被标明，静态脚本通过不替代语义检查。

## 整体结构与逻辑

- 模块有清楚的学习目标，每课有主要问题和新增理解，而非技术名称或源码文件的罗列。
- 每课所需前置知识已经建立或在使用处补足；没有依靠后文才成立的循环解释。
- 相邻课程边界能用问题、规则或可见结果说明，拆合有教学理由。
- 每一节回答前文自然产生的疑问，读者能解释为什么接着讲它。
- 优化方案从已经说明的成本引出，新方案引发的困难有后续解法，不能从“存在瓶颈”跳到公式或代码。
- 调整课程顺序后，目录、编号、术语、交叉引用和图片仍然一致。

## 重复内容

- 同一机制的定义、完整推导和完整算例各有明确归属，没有在前言、正文、图注、结尾重复展开。
- 推导与应用各有贡献：一处解释规则为何成立，另一处展示如何使用；重复的中间计算直接引用。
- 跨课回顾只补当前理解需要的信息，不重讲上一课，也不提前教授本课内容。
- 保留必要提醒和关键因果步骤，不以“去重”为由造成断层。

## 可理解性与可讲述性

- 开头能让读者知道本课要解释什么，不需要先读完一页术语或范围声明。
- 例子小而完整，输入、状态、结果可追踪；优化比较使用相同输入与计量口径。
- 公式变量在使用前定义，关键变换有理由，数值结论能对应到中间步骤。
- 新术语、硬件名词和缩写有必要的解释；不引入只增加记忆负担的别名。
- 源码片段解释行为与设计原因，不是逐行翻译，也不要求读者自行跳转多个文件补齐主线。
- 标题描述具体内容。把段落读出来时，指代、转折和前提足够清楚，不能只靠作者脑中的背景补全。
- 课程回顾、实验、选读、预告等是否出现由用户要求和教学目标决定，不按固定模板添加。

## 图片与渲染

- 配图解决一个具体理解困难，放在相应介绍附近；没有固定的开头图或配图数量要求。
- 对象、轴、形状、箭头、颜色和共享关系正确，不用箭头含糊混合时间顺序与数据依赖。
- 有足够的信息解释机制，又能在正常文档宽度读清；长段文字没有简单搬进图框。
- 正文、图片和图注互补。公式紧邻相应操作，不是一排孤立符号。
- 目标 Markdown/PDF 环境中的数学、矩阵换行、粗体、链接、图尺寸和分页实际可读；未渲染检查时不声称已验证。
- 图稿、Mermaid 骨架、生成图片和最终可用图的状态如实说明。

## 验收结论

先报告阻碍理解或影响事实的问题，再报告局部改进。若没有实质问题，直接说明，不重复大改已稳定内容。

只有主线连贯、重要结论和例子已核实、目标展示效果已检查时，才称为可录课版本。检查报告应区分已通过、未检查及仍有问题的项目；不要用统一评分掩盖某个关键缺口。
